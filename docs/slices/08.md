## 0. Decisiones tomadas para esta slice

**Proveedor de traducción: OpenRouter, no la API de Claude directa — decisión
del usuario, registrada en D16.** `docs/I18N.md` hablaba de "la API de
Claude"/`ANTHROPIC_API_KEY` porque no había otra opción sobre la mesa
cuando se escribió. Env var nueva: `OPENROUTER_API_KEY` (sólo servidor,
sólo admin). Dependencia nueva, propuesta y confirmada con el usuario: el
SDK `openai` (compatible con la API de OpenRouter), apuntado a
`baseURL: "https://openrouter.ai/api/v1"`. Es la única alta al stack
cerrado de `CLAUDE.md` para esta slice.

**Modelo: `openrouter/auto`, fijo en código.** Ruteo automático de
OpenRouter — un modelo distinto puede resolver cada llamada según el
prompt. Confirmado con el usuario. No compromete el invariante 6 (round-trip
de bloques): la validación estructural de más abajo rechaza cualquier
traducción que altere directivas, sin importar qué modelo la generó — la
variabilidad de modelo es un problema de costo/latencia, no de corrección.

**`OPENROUTER_API_KEY` es opcional en `env.ts`, no obligatoria.** Si fuera
obligatoria (como `BASE_DOMAIN`/`DATABASE_URL`), cada test existente de
`tests/acceptance/s1.test.ts` a `s7.test.ts` que hoy importa `src/app.js`
sin tocar esta variable dejaría de arrancar — un efecto colateral sobre
código de slices ya cerradas, por una funcionalidad que sólo usa el admin.
El módulo de traducción valida su presencia recién al llamarse; si falta,
el botón "Traducir" falla con un mensaje claro y el resto de la aplicación
sigue funcionando, tal como pide `docs/I18N.md` §8.

**Ningún cambio de esquema.** `lang`, `translation_group_id`,
`source_post_id`, `translated_at`, `source_updated_at` en `posts`, y `lang`
en `post_slugs`, ya existen desde D8 (S2). No hace falta ninguna migración
en esta slice.

**Routing `/en/`: se resuelve acá, no en S3.** `docs/I18N.md` §7 le asignaba
este trabajo a S3, pero `docs/slices/03.md` nunca lo incluyó y las rutas
públicas (`routes/public/space.ts`, `routes/public/post.ts`,
`routes/central/index.ts`) hardcodean `LANG = "es" as const` desde que se
escribieron — aunque el módulo de contenido ya acepta `lang` como parámetro
en cada función desde D8. Registrado en D16. Mecanismo: `spaceIndexRoutes` y
`postRoutes` pasan de ser plugins de Fastify a **fábricas que reciben
`lang`** y devuelven el plugin:

```ts
export default function postRoutes(lang: "es" | "en") {
  return function (fastify: FastifyInstance): void {
    // usa `lang` donde hoy usa la constante LANG
  };
}
```

`routes/public/index.ts` registra cada fábrica dos veces:

```ts
await fastify.register(spaceIndexRoutes("es"));
await fastify.register(postRoutes("es"));
await fastify.register(spaceIndexRoutes("en"), { prefix: "/en" });
await fastify.register(postRoutes("en"), { prefix: "/en" });
```

Sin ambigüedad de rutas: `/en/:slug` y `/:slug` son de distinta profundidad
para el router de Fastify (find-my-way), no compiten entre sí. `/en/c/:categoria`
sale gratis del mismo mecanismo — no lo pedía `docs/I18N.md` explícitamente,
pero es la extensión directa de "índices por idioma" (§7, línea de S3) y el
contenido ya está filtrado por `lang`. `renderCentralHome` (llamada directo,
no plugin, desde el handler `GET /` de `spaceIndexRoutes` cuando
`request.space` es `null`) gana un tercer parámetro `lang`.

**Enlaces entre espacios/central llevan el prefijo cuando corresponde.**
`centralUrlFor`/`spaceUrlFor` (duplicadas hoy en `post.ts`, `space.ts`,
`central/index.ts`) arman la URL a partir de `BASE_DOMAIN` y el `Host` de la
petición (`.claude/rules/Db.md`); ganan un sufijo `/en` cuando `lang ===
"en"`. Mismo criterio para `basePath` de la paginación de
`space-index.eta` (hoy `""` o `/c/{categoria}`) y para los `href` de la
barra de categorías.

**Diccionario de interfaz: objeto plano, resuelto en la ruta, no en la
plantilla.** `src/i18n/dictionary.ts` exporta un `Record<"es" | "en",
{...}>` de ~20 claves (`backToAll`, `categoriesLink`, `readingMinutesSuffix`,
`paginationPrev`, `paginationOf`, `rssOfSpace`, `spacesLink`, `tagsLink`,
`latestTitle`, `crossTagsTitle`, `archiveLabel`, `allCategoryLabel`,
`centralTagline`, etc. — inventario exacto en T3). Ninguna plantilla decide
idioma: cada ruta pública arma sus locales ya resueltos
(`it.strings.backToAll`, no `it.lang === "en" ? ... : ...` dentro del
`.eta`), igual que hoy `formatDateLong`/`formatDateShort` resuelven la
fecha antes de llegar a la vista. `src/i18n/dates.ts` reemplaza los tres
arreglos `MONTHS`/`MONTHS_SHORT` duplicados (`post.ts`, `space.ts`,
`central/index.ts`) por `formatDateLong(date, lang)`/`formatDateShort(date,
lang)` — se consolidan porque esta slice ya necesita la lista en inglés en
los tres lugares, no es una abstracción adelantada a un uso futuro.
`<html lang="es">` fijo en `post.eta`/`space-index.eta`/`central-index.eta`
pasa a `<html lang="<%= it.htmlLang %>">`.

**`name_en`/`slug_en` de categorías y tags (ya existen desde D8) no ganan UI
de edición en esta slice.** `docs/I18N.md` §7 no lo pide para S8 — sólo el
botón de traducción es sobre posts. Sin valor cargado, el criterio "cae al
español si falta" (§3) hace que la barra de categorías y los tags de una
página en inglés muestren el nombre en español hasta que una tarea futura
agregue esos campos al admin. Se anota en el WON'T DO para que no se cuele
durante la implementación.

**Traducir exige que el original esté publicado.** El diagrama de flujo de
`docs/I18N.md` §5 arranca en "post en español, publicado" — el botón
"Traducir" sólo aparece (y la ruta sólo actúa) cuando `post.lang === "es"`
y `post.status === "published"`. Un borrador en español no tiene botón de
traducción todavía.

**Reglas del traductor: prompt fijo en código, no por post.** El system
prompt de `src/modules/translation/openrouter.ts` codifica textualmente las
reglas de `docs/I18N.md` §5 (directivas intactas, código sin tocar, rutas y
enlaces literales, alt traducido, tono sin "mejorar"). Se le pide al modelo
que devuelva **un único objeto JSON** como contenido de la respuesta (sin
fences de Markdown), con las claves `title`, `excerpt`, `slug`, `bodyMd` —
no se usa el parámetro `response_format` de la API (no está garantizado que
todo modelo que `openrouter/auto` elija lo soporte); `JSON.parse` sobre el
contenido de la respuesta, y una respuesta que no parsea es una traducción
rechazada, igual que una que no pasa la validación estructural — "una
tirada de traducción se guarda entera o no se guarda" (§5).

**Validación estructural: cuenta, tipo y atributos de las directivas de
bloque, nada más.** Tal como fija `.claude/rules/Markdown.md` y
`docs/I18N.md` §5: se parsea el Markdown original y el traducido con
`remark-parse` + `remark-gfm` + `remark-directive` (sin `remark-rehype`,
no hace falta convertir a HTML para esto), se extrae la lista de nodos
`containerDirective`/`leafDirective`/`textDirective` de cada árbol
(`{ type, name, attrs }`, en orden) y se comparan con igualdad profunda. No
se verifica el contenido literal de bloques de código ni de URLs de
imagen/enlace — esas son reglas del prompt (§5), no algo que el código
verifique de vuelta; `docs/I18N.md` sólo pide comparar directivas.

**Persistencia: insertar el hermano en inglés si no existe, actualizar sus
campos traducibles si ya existe.** "Retraducir es volver a apretar el
botón" (§4) — pero retraducir nunca toca `slug` ni `status` de un hermano
que ya existe: esos campos ya son del autor (el slug pasó por su
confirmación al crearse, invariante 5). Sólo se refrescan `title`,
`excerpt`, `bodyMd`, `bodyHtml`, `translatedAt` y `sourceUpdatedAt`. Al
crear por primera vez, el slug propuesto por el modelo se ajusta con un
sufijo numérico (`-2`, `-3`, ...) si ya existe otro post en ese
`(space_id, lang)` — no hay pantalla intermedia de confirmación de slug
antes de guardar (el autor lo edita después, como cualquier otro campo del
post, en `/admin/posts/{id}`).

**Errores de traducción se muestran con el mismo patrón que ya usa el
login:** redirect con parámro de query (`/admin/posts/{id}?translateError=…`),
la vista lee el mensaje y lo muestra como texto plano — no hay
infraestructura de flash-session en el proyecto y no hace falta agregarla
para esto.

**`hreflang`/`canonical`/`x-default` van en `post.eta` únicamente**, vía
una extensión del partial `partials/head.eta` (gana `canonical` y
`alternates: { hreflang, href }[]` opcionales). El `canonical`/OG genérico
de central-vs-subdominio que menciona el viejo S8 (ahora S9, "Sitio central
y distribución") no es parte de esta slice — acá el único "canonical"
relevante es que cada idioma es canónico de sí mismo frente a su hermano de
traducción, no frente al sitio central.

---

## 1. Qué prueba esta slice

Que el modelo de datos que D8 dejó listo desde S2 (`lang`,
`translation_group_id`, `source_post_id`, `translated_at`,
`source_updated_at`) sirve de punta a punta: un post publicado en español
se traduce con un click, la traducción vuelve como borrador revisable, una
traducción que rompe la estructura de bloques se rechaza sin tocar la base,
y el sitio público sirve `/en/` sobre cualquier espacio y sobre el central,
con el enlace entre idiomas correcto cuando ambas versiones están
publicadas. Prueba también que "editar el original en silencio no
desactualiza en silencio la traducción" — el admin tiene que avisarlo.

## 2. Tareas

Cada tarea declara los archivos que puede tocar. Nada fuera de esa lista.

### T1 — Dependencia y configuración

Agrega `openai` a `package.json`. `OPENROUTER_API_KEY` opcional en
`env.ts` (§0). Entrada nueva en `.env.example`.

**Archivos:** `package.json`, `pnpm-lock.yaml`, `src/config/env.ts`,
`.env.example`.

### T2 — Routing `/en/`

`spaceIndexRoutes`/`postRoutes` pasan a fábricas `(lang) => (fastify) =>
void` (§0). `renderCentralHome` gana el parámetro `lang`. `routes/public/index.ts`
registra las cuatro combinaciones. `centralUrlFor`/`spaceUrlFor` y el
`basePath` de paginación agregan el sufijo `/en` cuando corresponde. Sin
cambios de plantilla todavía (eso es T3).

**Archivos:** `src/routes/public/index.ts`, `src/routes/public/space.ts`,
`src/routes/public/post.ts`, `src/routes/central/index.ts`.

### T3 — Diccionario de interfaz y fechas por idioma

`src/i18n/dictionary.ts` (nuevo, objeto plano `es`/`en`) y `src/i18n/dates.ts`
(nuevo, `formatDateLong`/`formatDateShort` por idioma, reemplaza los tres
arreglos `MONTHS`/`MONTHS_SHORT` locales). Las tres rutas públicas arman
`it.strings`/`it.htmlLang` a partir de `lang` en vez de copy fijo. Las tres
plantillas (`post.eta`, `space-index.eta`, `central-index.eta`) y el
partial `space-nav.eta` leen `it.strings.*`/`it.htmlLang` donde hoy tienen
texto o `lang="es"` fijos.

**Archivos:** `src/i18n/dictionary.ts` (nuevo), `src/i18n/dates.ts` (nuevo),
`src/routes/public/space.ts`, `src/routes/public/post.ts`,
`src/routes/central/index.ts`, `src/views/post.eta`,
`src/views/space-index.eta`, `src/views/central-index.eta`,
`src/views/partials/space-nav.eta`.

### T4 — Validación estructural del Markdown traducido

Función pura `extractDirectiveShape(markdown): DirectiveShape[]`
(`remark-parse` + `remark-gfm` + `remark-directive`, sin red ni base) y
`directiveShapesMatch(a, b): boolean`. Sin dependencia de
`src/markdown/blocks/registry.ts` — esto compara la forma sintáctica de las
directivas, no necesita saber qué bloque es cada una.

**Archivos:** `src/modules/translation/validate.ts` (nuevo).

### T5 — Cliente de OpenRouter

`translateContent({ title, excerpt, bodyMd }): Promise<{ title, excerpt,
slug, bodyMd }>`. SDK `openai` apuntado a OpenRouter (§0), system prompt
con las reglas del traductor de `docs/I18N.md` §5, modelo
`openrouter/auto`, parseo de JSON de la respuesta. Tira si falta
`OPENROUTER_API_KEY`, si la llamada falla, o si la respuesta no parsea como
el objeto esperado.

**Archivos:** `src/modules/translation/openrouter.ts` (nuevo).

### T6 — Orquestación y persistencia

`translatePost(originalId): Promise<{ id: string }>`: carga el original
(tira si no es `lang: "es"` o no está `published`), llama a T5, valida con
T4 (tira `TranslationValidationError` con el detalle del mismatch si no
coincide), resuelve colisión de slug con sufijo numérico, inserta o
actualiza el hermano en inglés dentro del mismo `translation_group_id`
(§0). `modules/content/posts.ts` gana `findTranslationSibling(translationGroupId,
excludeId)` y las columnas nuevas que necesita el admin
(`lang`, `translationGroupId`, `sourcePostId`, `sourceUpdatedAt` en
`PostDetail`; `lang` e `isStale` en `PostSummary`, calculado con un `LEFT
JOIN` contra el `updatedAt` del `sourcePost`).

**Archivos:** `src/modules/translation/translate.ts` (nuevo),
`src/modules/content/posts.ts`.

### T7 — Admin: botón de traducción, aviso de desactualizada, ruta

`POST /admin/posts/:id/translate` en `routes/admin/posts.ts`: llama a
`translatePost`, redirige al hermano en inglés si sale bien, o de vuelta al
original con `?translateError=` si sale mal (§0). `form.eta` gana el botón
"Traducir al inglés" (sólo `lang === "es"` y `status === "published"`),
enlace al hermano si ya existe, aviso de traducción desactualizada, y el
mensaje de `translateError` si viene en la query. `list.eta` gana columna
de idioma y una marca junto al título cuando `isStale`.

**Archivos:** `src/routes/admin/posts.ts`, `src/views/admin/posts/form.eta`,
`src/views/admin/posts/list.eta`.

### T8 — Enlace entre idiomas en el sitio público

`findPublishedPost` (o una función nueva a su lado en
`modules/content/posts.ts`) resuelve el hermano publicado del otro idioma
dentro del mismo `translation_group_id`, si existe. `partials/head.eta`
gana `canonical` y `alternates` opcionales (§0); `routes/public/post.ts`
arma `canonical` (self), `alternates` (el propio + el hermano si está
publicado) y `x-default` (apunta siempre a la versión en español, sea el
post actual o el hermano).

**Archivos:** `src/modules/content/posts.ts`, `src/routes/public/post.ts`,
`src/views/partials/head.eta`, `src/views/post.eta` (pasa los nuevos datos
al include de `head`).

### T9 — Tests

Unit: `directiveShapesMatch` (idéntico, atributo distinto, directiva de más
o de menos, tipo distinto, cero directivas en ambos) en
`tests/unit/translation/validate.test.ts`. Acceptance nueva
(`tests/acceptance/s8.test.ts`, contra Postgres de dev): mockea
`globalThis.fetch` con `node:test`'s `mock.method` (sin dependencia nueva
de testing) para no golpear la red real ni gastar créditos — un post
publicado con galería y bloque de código se traduce con una respuesta
simulada que preserva la estructura → aparece como borrador en
`/en/{slug}` sólo tras publicarse; una respuesta simulada con una directiva
de menos → se rechaza, no se crea/actualiza ninguna fila; editar el
original tras traducir → el admin marca la traducción como desactualizada;
`/en/` y `/en/{slug}` resuelven sobre un espacio y sobre el dominio
central; un post sin traducir no aparece en el índice del espacio en
`/en/` ni en la home central en inglés.

**Archivos:** `tests/unit/translation/validate.test.ts` (nuevo),
`tests/acceptance/s8.test.ts` (nuevo).

## 3. WON'T DO

Recordatorio para cualquier tarea de esta slice — no se construye nada de
esto todavía, aunque parezca dos líneas:

```text
comentarios
usuarios múltiples y roles
newsletter
analytics propio
temas intercambiables por UI
sistema de plugins
búsqueda full-text
```

Específico de S8: traducción a idiomas más allá de es/en, traducción
automática al guardar o detección de idioma del visitante (§1 de
`docs/I18N.md` lo prohíbe explícitamente), traducción en sentido
inglés→español, edición del texto traducido dentro del propio flujo de
traducción (se edita en `/admin/posts/{id}` como cualquier post), UI para
cargar `name_en`/`slug_en` de categorías y tags, elegir el modelo de
OpenRouter desde el admin, reintentos automáticos o caché de llamadas a
OpenRouter, feeds y sitemaps por idioma (quedan para S9, D16), canonical/OG
genérico de central-vs-subdominio (también S9), publicación programada de
la traducción.

## 4. Criterio de aceptación

```text
✓ traducir un post publicado con galería y bloque de código, desde el
  admin, sin tocar Markdown a mano → la estructura de bloques se conserva
  exacta en el borrador resultante
✓ la traducción se crea siempre como borrador, nunca publicada
✓ editar el original después de traducir → la traducción aparece marcada
  como desactualizada en la lista de posts del admin
✓ post con ambas versiones publicadas → hreflang recíproco y x-default en
  las dos páginas
✓ post sin traducir → no aparece en el índice del espacio en /en/ ni en la
  home central en inglés
✓ una respuesta de traducción con directivas alteradas se rechaza, se
  muestra el error y no se guarda ninguna fila
✓ /en/{slug}, /en/, /en/c/{categoria} resuelven sobre cualquier espacio, y
  /en/ resuelve sobre el dominio central
✓ corriendo en esta máquina vía docker compose, gestionado por dockge
✓ pnpm lint && pnpm typecheck && pnpm test en verde
```
