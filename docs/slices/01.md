## 0. Decisiones tomadas para esta slice

Estas decisiones se conversaron y cierran antes de escribir código. No se reabren
dentro de la slice.

**Proxy/TLS: Caddy, no Traefik.**
El stack original (`SPEC.md`, `CLAUDE.md`) fijaba Traefik. Ya hay Caddy + dockge
corriendo en la máquina que sirve de servidor, así que se actualizó la spec para
usar Caddy. Caddy resuelve DNS-01 con el plugin del proveedor de DNS que
corresponda, igual que hubiera hecho Traefik.

**Sin dominio real todavía → sin TLS real todavía.**
DNS-01 necesita un dominio real apuntando a esta máquina, y ese dominio no está
decidido aún (Design.md usa `divermente.com` como marca, pero no está confirmado
ni apuntado). Por lo tanto:

- S1 corre sobre `*.localhost` en HTTP plano, servido por Caddy en esta máquina.
- El criterio de aceptación de "certificado wildcard válido" de `PLAN.md` **no
  se cumple en esta corrida** — queda pendiente explícito, no descartado (ver §4).
- El código no debe asumir nunca `localhost` ni ningún dominio fijo (ver §2,
  regla de `BASE_DOMAIN`), así que el día que haya dominio real, activar TLS es
  una tarea de infraestructura (Caddyfile + DNS-01), no un cambio de código.

**Servidor: esta máquina, vía dockge.**
El despliegue "real" de esta slice es esta máquina, administrada con dockge.
No hay que provisionar nada nuevo.

**Espacios de prueba: `nutricion` e `ideas`.**
De los tres espacios de `Design.md` (nutrición, ideas, ia), se usan los dos
primeros. Contenido mínimo, no necesita ser real todavía — el objetivo de S1 es
probar el pipeline, no publicar contenido.

## 1. Qué prueba esta slice

Del plan: pipeline de Markdown, routing por `Host`, TLS wildcard. El TLS queda
en pausa por falta de dominio (§0), así que esta corrida prueba las otras dos
cosas de punta a punta, más el empaquetado en Docker Compose.

## 2. Tareas

Cada tarea declara los archivos que puede tocar. Nada fuera de esa lista.

### T1 — Proyecto base: Node 22 + TS + Fastify + Eta

Scaffolding mínimo: servidor Fastify que arranca, motor de vistas Eta
configurado, un endpoint de salud.

**Archivos:** `package.json`, `tsconfig.json`, `src/server.ts`, `src/views/`,
`.gitignore` (si hace falta).

### T2 — Middleware de resolución de espacio por `Host`

Antes de cualquier ruta, resuelve el espacio a partir de la cabecera `Host` y lo
deja en `request.space`.

Sin base de datos todavía (llega en S2/S3), así que la fuente de la lista de
espacios es un mapa mínimo en config — **no hardcodeado en la lógica de
routing**, para que S3 lo reemplace por una consulta a `spaces` sin tocar el
middleware. Ver `.claude/rules/Db.md`: el dominio base sale de `BASE_DOMAIN`
(env var, validada con Zod), nunca de un literal `localhost` o de un `if`
por ambiente. El mismo middleware tiene que andar en `nutricion.localhost:PORT`
hoy y en `nutricion.divermente.com` el día de mañana sin cambiar una línea.

Host desconocido → 404.

**Archivos:** `src/middleware/space.ts`, `src/config/env.ts` (o equivalente
para `BASE_DOMAIN` y el mapa de espacios).

### T3 — Pipeline Markdown → HTML

`remark-parse → remark-gfm → remark-directive → remark-rehype → rehype-shiki →
rehype-sanitize → rehype-stringify`, según el orden fijado en
`.claude/rules/Markdown.md`.

`remark-directive` se cablea desde ahora aunque todavía no exista ningún bloque
registrado (el registro llega en S6) — así el pipeline no se toca cuando
aparezca el primer bloque.

**Archivos:** `src/markdown/pipeline.ts`.

### T4 — Ruta `/{slug}`

Lee el `.md` del espacio resuelto en `request.space`, lo pasa por el pipeline,
renderiza con Eta. Slug inexistente → 404.

**Archivos:** `src/routes/public/`, `src/views/post.eta` (o equivalente).

### T5 — Contenido de prueba

Un `.md` por espacio, contenido distinto y verificable a simple vista.

**Archivos:** dos archivos markdown de prueba (ubicación a definir en T1/T2,
p. ej. `content/nutricion/hola.md` y `content/ideas/hola.md`).

### T6 — Docker Compose + Caddy

`docker-compose.yml` con el servicio de la app; `Caddyfile` que enruta
`nutricion.localhost` e `ideas.localhost` a la app por HTTP (sin TLS por §0).
Integrado a dockge en esta máquina.

**Archivos:** `docker-compose.yml`, `Caddyfile`, `Dockerfile`.

## 4. Criterio de aceptación

```text
✓ GET http://nutricion.localhost:PORT/hola   → 200, HTML del md de nutrición
✓ GET http://ideas.localhost:PORT/hola       → 200, HTML del md de ideas, distinto
✓ GET http://otroespacio.localhost:PORT/     → 404
✓ corriendo en esta máquina vía docker compose, gestionado por dockge
```

**Pendiente explícito, no parte de esta corrida:** certificado wildcard válido
vía DNS-01. Requiere: dominio real decidido y apuntado (registros DNS) a esta
máquina, más credenciales de API del proveedor de DNS cargadas en Caddy. Se
activa como tarea de infraestructura aparte en cuanto exista el dominio, sin
tocar código de aplicación (ver regla de `BASE_DOMAIN` en §2).
